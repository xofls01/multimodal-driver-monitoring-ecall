# 휴대전화 오검출 수정

The new A의 책상과 핸들 주변에 휴대전화 후보가 표시되는 문제를 실제 원본 영상으로 확인했다. 실제 휴대전화는 반대쪽 손에 있었으며, 배경의 약한 검출이 손 주변 후보 조건을 통과했다.

## 수정

기존 추적기는 한 물체가 확인되면 다른 위치의 새 후보도 즉시 표시할 수 있었다. 후보별로 위치 대응과 확인 횟수를 따로 관리하도록 바꿨다. 최소 두 번 확인하는 설정이 각 물체에 적용되며, 한 물체의 검출이 다른 물체의 유지 시간을 갱신하지 않는다. 측정하지 않은 프레임은 확인 횟수에 더하지 않고 오래된 미확인 후보도 만료시킨다.

손 근처라는 사실만으로 휴대전화 후보를 통과시키지 않는다. 후보 주변을 다시 잘라 같은 검출 모델로 휴대전화가 재검출되는지 확인한다. 재검출 상자가 원래 후보와 겹치는지도 확인해, 같은 확대 영상의 다른 물체가 후보를 대신 확인하지 않도록 했다.

현재 구현 설정은 주변 여백 0.6, 재검출 점수 0.25, 상자 겹침 IoU 0.3, 원래 검출과 재검출 점수의 기하평균 0.35다. 이 값들은 객체 검출의 시험용 품질 설정이며 논문에서 확인된 위험 기준이나 확률이 아니다. 두 점수는 같은 모델의 다른 영상 입력에서 나온 값으로 독립적인 확률로 설명하지 않는다.

기존 전체 영상과 손 확대 검출의 낮은 후보 점수는 유지한다. 실제 폰의 기울어진 모양을 과하게 거르지 않도록 prototype의 최대 가로세로비를 3.3에서 4.5로 조정하고, 추가 외형 재검증과 크기 및 손 위치 검사를 함께 적용한다. 낮은 최초 점수라도 확대 재검증이 충분하면 통과할 수 있다. legacy 비교 설정에서는 새 외형 재검증을 끌 수 있도록 했다.

화면의 특정 영역을 막거나, 휴대전화를 한 개만 남기거나, 시나리오와 시간을 이용해 검출을 숨기지 않는다. 실제로 두 휴대전화가 각각 확인되면 두 개를 추적할 수 있다. 화면의 PHONE CANDIDATE는 여전히 모델의 물체 후보이며 확정적인 사실을 뜻하지 않는다.

## 실제 영상 확인

The new A, E4, D3를 수정된 코드로 다시 추론하고 현재 판단 763개를 publish()에 전달했다. TCP 모의 수신기에서 Normal, Caution, Danger를 확인했다. 실제 Unity Editor와 차량 물리는 실행하지 않았다.

The new A에서 검토한 오른쪽 배경 영역에 후보가 표시된 분석 시점은 기존 52개에서 수정 후 0개였다. 휴대전화를 들고 있는 것으로 검토한 3.5~17.5초의 왼쪽 손 영역에는 기존 150/199개, 수정 후 156/199개의 분석 시점에 후보가 있었다. 시작 0~2.5초에는 두 실행 모두 휴대전화 후보가 없었다.

이 영역과 시간은 해당 영상의 전후 비교에만 사용한 수동 검토 구간이다. 실제 검출 코드의 필터가 아니며, 전체 객체 검출의 정밀도나 재현율을 검증한 결과도 아니다. 가림과 반사 등으로 실제 폰이 누락되는 구간은 남아 있다.

세 영상의 상태와 판단 이유를 시점별로 대조한 결과 변경은 0개였다. 눈 감김과 자세, 경고 및 정차 기준은 수정하지 않았다. 새 A에서 아래보기를 눈 감김으로 해석하는 별도 문제도 이번 수정으로 해결한 것은 아니다.

자동 테스트 185개를 통과했다. 새 후보의 독립 확인, 개별 만료, 같은 프레임의 중복 검출, 다른 물체를 통한 잘못된 재검증, 낮은 최초 점수의 실제 폰 후보 통과 등을 확인했다.

## 위치와 실행

- src/driver_state_tools/object_tracking.py: 물체별 확인과 만료
- src/driver_state_tools/vision_pipeline.py: 손 주변 후보의 확대 재검증
- config/prototype/vision_baseline.json: 기본 실행의 품질 설정
- tests/test_object_tracking.py와 tests/test_phone_context.py: 회귀 검증
