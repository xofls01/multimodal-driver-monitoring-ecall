# 판단 기준 개정본 작업 기록

2026-11-11. 통합 명세에 따른 별도 복사본이다. 원본 실행 폴더와 기존 GitHub용 폴더는 수정하지 않았다. 모델 추가 학습과 Git 커밋, 푸시는 하지 않았다.

## 실제 기본 설정

기본은 `config/decision_rules.json`의 literature 모드다. 기존 설정은 `config/legacy/`에서 재현한다.

- 눈 감김 1.5초에 주의, 3초에 prolonged_eye_closure 이유 추가.
- 검증된 눈 감김 6초에만 해당 눈 감김 정차 경로 사용.
- 전방 이탈 연속 3초 또는 최근 30초 중 누적 10초에 주의.
- 실제 주의분산 경고 표시 확인 후 계속 관측된 AWAY 3초에 정차 요청.
- 검토된 입 측정과 최대 벌림 보정이 있을 때 지속 입 벌림 3초에 주의.
- 완성된 고정 60초 구간의 눈 감김 비율 20%를 장기 경고에 사용.
- 꾸벅임은 개인별 두 경계와 하강 및 복귀 속도 범위를 요구하는 별도 사건 검출기.
- 모든 주의의 3초 합산, 과거 반복 횟수, 가슴 손동작과 상체 각도의 독립 경고는 새 모드에서 제외.
- 외부 경고 5초와 버튼 무응답 규칙은 새 모드에 섞지 않고 기존 모드에 보존.

vision_baseline.json의 legacy_diagnostic_only_parameters 목록은 기존 관찰 특징 계산용 설정이다. 새 모드의 경고는 decision_rules.json과 새 사건 검출기에서 결정한다. 기존 8초, 35%, 65%의 대리 지표 설정을 새 경고 기준으로 사용하지 않는다.

## 준비 상태와 한계

눈 기준은 검토된 눈 뜸 구간의 평균 EAR로 구성한다. build_eye_calibration.py는 원본과 관찰 로그의 SHA256, 검토 구간을 확인해 프로필을 만든다. 검토되지 않은 시작 장면을 눈 뜸으로 가정하지 않는다. 양쪽 EAR 평균과 시간상 평균, 계수, 요청 및 실제 임계값, 제한 적용 여부, 히스테리시스를 기록한다.

D2는 최초 0~0.8초의 유효 얼굴 표본이 2개뿐이라 보정을 거절했다. 이후 별도로 확인한 0.73~1.2초의 눈 뜬 표본 8개를 사용했다. 평균 EAR 0.332666, 요청 및 적용값 0.249500이다. 별도 검토 구간의 눈 뜸은 3/3이 일치했지만 눈 감김은 2/9만 일치했다. eye_validation.passed는 false이며 해당 프로필의 눈 감김 정차 경로는 비활성이다. 이 숫자는 선택한 표본의 대응 검사이며 데이터셋 정확도가 아니다. 통과시키려고 임계값을 조정하지 않았다.

시선은 실제 가중치 미연결이다. 어댑터와 오류 및 준비 상태 처리는 구현했으나 R4 모델을 내려받아 배치한 상태가 아니다. UNKNOWN을 표시한다. 입력과 전처리, 클래스 순서, 카메라와 도로 전방의 대응 검증도 남아 있다.

꾸벅임은 삭제하지 않았다. 후보, 하강 확인 후 의심, 복귀 중, 완료 사건을 구현하고 테스트했다. 눈을 뜬 하강과 경계 전 복귀는 취소하고 관측 누락을 완료로 세지 않는다. 경계와 속도 자료가 없어 needs_calibration이다. 기존 방식은 재현용 모드에 남아 있다.

입 벌림은 R1의 비대칭 마지막 항을 임의로 정정하지 않았다. 원문 형태의 계산 경로는 검토된 점 대응과 5초 최대 벌림 프로필을 요구한다. 해당 보정이 없어 새 경고는 미준비다. 기존 MAR과 관찰 정보는 보존한다.

60초 비율은 짧은 영상에서 해당 항목만 COLLECTING이다. 짧은 파일을 이어 붙이지 않는다. 결측을 눈 뜸으로 채우거나 유효 시간으로 분모를 바꾸지 않는다. 구간 결과는 다음 60초 결과까지 최대 60초 유지한다. 새 구간이 낮음 또는 불명으로 나오면 이전 장기 경고를 해제한다. 이 유지 정책은 구현 설계다.

누적 이탈 10초 조건을 한 번 사용하면 누적량이 10초 아래로 내려갔다 올라올 때 재활성화한다. 전방 복귀 후 과거 이력만으로 매 프레임 재경고하지 않는다. 새로운 연속 3초 이탈은 별도 사건이 될 수 있다. 이 중복 억제는 구현 설계다.

기본 실행은 시선과 눈 보정이 미준비여서 NORMAL 대신 UNAVAILABLE이 나올 수 있다. 유효한 다른 경고가 있으면 CAUTION을 유지한다. full_system_ready는 전체 명세 준비 여부, vision_available은 현재 전달 가능한 판단 여부이며 서로 다르다. 부분 관측 경고를 전체 시스템 준비 완료로 설명하지 않는다.

가슴 부근 손이나 상체 기울기만 나타나는 E 시나리오는 새 모드에서 자동 응급 경고하지 않는다. 향후 동시 수집한 ECG/PPG 시각과 신호 품질, 센서 상태, 별도 버튼 응답과 실제 경고 시각이 필요하다. 결측이나 잡음을 심정지 정답으로 간주하지 않는다.

## 현재 분석에서 Unity로 전달되는 경로

run_vision_baseline.py --unity → RevisionSession.update() → 현재 Decision 생성 → AnalysisPublisher.publish() → UnityStateServer.publish() → TCP NDJSON 전송.

분석 시점마다 실제로 생성한 판단을 발행한다. 빠른 분석에서 잠깐 나온 Danger가 다음 Normal로 덮이기 전에 한 번 전달되도록 우선 전송하며, 원래 생성 시각에 대한 신선도 검사는 유지한다. serve_unity.py의 저장 로그 재생과 구분했다. heartbeat는 행동 시간을 늘리지 않는다. 0.75초 신선도 검사를 유지하며 오래된 결과는 vision_state=unavailable, vision_available=false와 prediction_stale로 전달한다. 구버전 호환용 driver_state=Caution이어도 새 C#은 가용성 필드로 일반 주의와 구분한다.

상태, 이유, 지속 시간, 시각, 경고 요청 ID, 실제 경고 발행 시각과 출처, 기능별 준비 상태를 전달한다. 요청 전송은 표시 확인이 아니다. Unity 경고 UI는 활성화된 렌더 프레임 이후 ACK를 보내며 Python은 이를 현재 영상 시각에 대응시켜 다음 관측부터 사용한다. 과거로 소급하지 않는다. --show의 OpenCV 표시는 별도 출처로 기록한다. 저장 영상에 그림을 그리는 것만으로 실제 경고 타이머를 시작하지 않는다.

Normal은 기존 운전 제어 모드 유지, Caution은 경고 UI와 소리, Danger는 EmergencyPullOverController.TriggerEmergency() 호출 경로다. 정차 요청은 별도로 유지해 Normal이나 Unavailable로 취소하지 않는다. 명시적인 비상 상태 해제 이후 정차 상태에서만 ResetStopRequestLatch()를 호출할 수 있다. 카메라 상태와 차량 대응 상태는 별개다.

## 테스트와 실제 실행

단위 및 회귀 테스트 134개 통과. 눈 1.5/3/6초, 이탈 3초, 30초 중 누적 10초, 경고 표시 확인 후 3초, UNKNOWN과 간격 변화, 원인 변경, 복귀, 세션 변경, 60초 결측 범위를 확인했다. 기존 모드 테스트는 보존한 기존 설정으로 실행한다.

분석 진입점과 실제 TCP를 함께 쓰는 테스트에는 합성 관측값을 사용했다. 현재 판단이 publish()에 전달되고 Python 모의 수신기에 Normal, Caution, Danger와 판단 불가가 도착하는 것을 확인했다. 테스트의 표시 ACK와 정차 유지 상태는 모의 동작이며 실제 Unity 렌더링이나 차량 물리 검증이 아니다.

실제 D2, E4, N1도 새 코드로 분석하고 프레임마다 현재 판단을 발행했다. 상세 수와 상태는 outputs/revision_actual/verification.json 및 프레임과 TCP 로그에 있다. 원본 영상 해시는 실행 전후 대조했다. 실제 영상에서 모든 상태가 나왔다고 주장하지 않는다. rPPG는 별도 계산과 저장을 유지하며 판단 입력으로 사용하지 않는다.

Unity Editor를 직접 실행하지 않았다. 이 환경에는 Editor와 전체 차량 프로젝트가 없고 연결 패치만 있다. C# 분기, 호출, ACK와 정차 유지 구조를 확인 및 수정했지만 컴파일, 씬 참조, 경고 UI와 소리, 갓길 이동과 감속, 정차, e-Call까지 검증한 것은 아니다.

실제 Unity에서는 두 C# 파일 교체와 씬 참조 확인 후 Normal의 주행 제어 유지, Caution의 UI와 소리 및 ACK, Danger의 정차 시작, 이후 Normal과 Unavailable에서 정차 유지, 통신 중단의 인식 불가 표시를 확인해야 한다. 미준비 실제 영상에서 Danger가 나오도록 임의 규칙을 더하지 않는다.

## 실행과 추가 자료

README의 sh run.sh는 복사본의 환경을 우선 사용하고 없으면 같은 상위 폴더 원본의 가상환경을 읽는다. 다른 PC에서는 requirements-lock.txt로 별도 환경을 만든다. 원본 코드와 가중치는 변경하지 않는다.

새 분석과 Unity 전송은 sh run.sh --input data/source_videos/D/D2.mp4 --calibration-profile config/profiles/D2_eye_profile.json --output outputs/new_unity_trial --unity로 실행한다. D2 프로필은 눈 감김 정차 검사를 통과하지 않아 해당 경로로 정차하지 않는다. --show는 현재 화면을 띄운다.

기존 모드는 --config config/legacy/vision_baseline.json --rules config/legacy/decision_rules.json을 함께 명시한다. 새 결과 폴더를 사용한다.

문헌별 대응은 [LITERATURE_MAPPING.md](LITERATURE_MAPPING.md), 파일별 변경은 [CHANGED_FILES.md](CHANGED_FILES.md), 원래 전달문은 [revision_spec.md](revision_spec.md)에 있다.
