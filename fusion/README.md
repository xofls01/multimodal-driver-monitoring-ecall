# 통합 판단 알고리즘 (생체신호 + 비전 + CAN)

생체신호, 비전, 차량 CAN(조향·가속·제동)을 합쳐 정상·주의·위험을 판단하고 Unity의 `driver_state`(`N/D/A/E`)로 내보낸다.
연구용 프로토타입이며 의료 진단용이 아니다. 임계값은 `fusion/config.py`에 있다.

## 판단 기준

### 위험 (`E`: 비상 정차 + e-Call, `reset()` 전까지 유지)

| 조건 | 판단 시점 |
|---|---|
| 생체 위험 또는 강한 생체 주의 + (눈 감김 3초 이상 또는 쓰러진 자세) + 최근 5초 조작 없음 | 즉시 |
| 생체 위험 + 경고 후 무응답 | 5초 |
| 눈 감김 또는 쓰러진 자세 + 조작 끊김 + 경고 후 무응답 | 5초 (눈 감김 시작부터 약 7초) |
| 눈 감김 또는 쓰러진 자세 + 조작을 읽을 수 없음(크루즈, CAN 끊김) + 경고 후 무응답 | 10초 (눈 감김 시작부터 약 12초) |
| 강한 생체 주의 + 경고 후 무응답 | 조작 끊김이면 5초, 아니면 10초 |
| 손-가슴 동작 + 생체 이상 + 경고 후 무응답 | 5초 |
| 전방 이탈 지속 + 경고 후 무응답 | 12초 (이탈 시작부터 약 14초) |
| 비전과 생체가 모두 측정 불가 + 15초 무조작 + 경고 후 무응답 | 10초 |
| 생체 위험 + 비전 정상 + 조작을 읽을 수 없음 + 무응답 | 30초 |

강한 생체 주의는 `NO_PULSE_UNCONFIRMED`, `HEART_PAUSE`, `*_UNCONFIRMED`다. 생체 쪽이 `needs_second_opinion`으로 넘긴 사유 중, 다른 센서가 정상이라고 반박한 `SENSOR_CONFLICT`만 뺐다.

### 주의 (경고)

| 분류 | 조건 | Unity |
|---|---|---|
| 졸음 | 눈 감김, PERCLOS, 하품, 긴 깜빡임 반복, 고개 끄덕임 반복, 토크 없이 쏠린 뒤 복귀 조향 1회, 토크 정보 없이 쏠림 후 복귀·급제동 60초 안에 2회 | `D` |
| 전방 이탈 | 전방 이탈, 고개 방향 이상, 짧은 이탈 반복, 누적 이탈 | `A` |
| 건강 | 생체 주의, 응답한 운전자의 생체 위험, 상체 기울어짐, 손-가슴 동작 | `A` (임시) |
| 시스템 | 시작 20초 뒤에도 비전과 생체를 모두 측정할 수 없음 | `A` (임시) |

### 정상 (`N`)

위 조건이 없고 운전자 상태를 측정하는 입력이 하나 이상 살아 있다. 정상이어도 끊긴 입력은 `coverage`로 표시한다.

시작 20초 안에 비전과 생체가 모두 측정 불가이면 정상이라고 하지 않고 `unavailable`을 낸다. 이때 Unity 코드는 `N`이다. 위험 근거가 나오면 시작 중에도 판단한다.

### 응답 인정 기준

- 경고 뒤 **구분되는 조작 2회**(0.5초 이상 떨어진 조향·가속·제동 변화) 또는 버튼 1회
- 응답 뒤 근거가 남아 있으면 다시 확인한다. 행동 근거는 10초, 생체 위험은 60초 뒤다.
- 근거를 낸 입력이 정상을 직접 확인하면 확인을 취소한다. 입력이 끊기면 취소하지 않는다.

## 이렇게 정한 이유

**점수 합산이 아니라 규칙표로 정했다.** 세 입력을 함께 라벨링한 데이터가 없어 가중치의 근거를 댈 수 없다. 규칙표는 위험 판단마다 이유를 사유 코드로 남길 수 있다.

**입력마다 답하는 질문이 다르다.** 그래서 서로 대체하지 않고 역할을 나눴다.

| 입력 | 답하는 질문 | 혼자 말할 수 없는 것 |
|---|---|---|
| 생체신호 | 몸에 이상이 있는가 | 운전을 계속할 수 있는가 |
| 비전 | 겉으로 어떻게 보이는가 | 의식이 있는가 (눈을 뜬 채 의식이 없을 수 있다) |
| CAN | 차를 조작하고 있는가 | 왜 조작하지 않는가 (직선로일 수 있다) |

**위험의 문턱을 높게 뒀다.** Unity에서 `E`는 한 번 걸리면 취소되지 않고 비상 정차와 e-Call까지 진행된다. 대신 주의는 낮은 문턱으로 일찍 울리고, 진짜 위험은 경고에 응답하지 못하는 것으로 가려낸다. 전체 판단의 중심에 응답 확인을 둔 이유다.

**두 근거가 겹치면 기다리지 않는다.** 심장 근거와 쓰러진 모습은 서로 다른 입력에서 나온 것이라 함께 틀릴 가능성이 낮고, 심정지라면 몇 초가 중요하다. 합성 심정지에서 박동 소실 약 5초 뒤 위험이 된다.

**조작 중인 운전자의 생체 위험은 주의로 둔다.** 150 bpm 이상이어도 차를 조작한다면 스스로 차를 세울 수 있다. 이 경우 강제 정차가 오히려 위험할 수 있고, 생체 근거만으로 잘못 판정했을 때의 비용도 크다. 경고를 유지하고 60초마다 다시 확인한다. 제안서가 무조건 위험을 요구한다면 `bio_danger_immediate=True`로 바꾼다.

**CAN은 값이 아니라 변화를 본다.** 쓰러진 운전자의 발이 페달을 누르고 있으면 가속값은 크게 나오지만 조작은 아니다.

**한 번의 조작은 응답으로 인정하지 않는다.** 쓰러지면서 핸들을 건드린 움직임을 응답으로 받으면 비상 정차가 취소된다.

**크루즈에서는 CAN을 응답으로 쓰지 않는다.** Unity의 Cruise는 조향을 0으로 고정하고 페달 값을 제어기가 만든다. `control_mode`가 `Manual`일 때만 운전자 조작으로 본다.

**무조작 단독으로는 경고하지 않는다.** 직선로에서는 핸들을 안 움직여도 정상이다. 비전이 정상이면 사유만 남기고, 비전이 없을 때만 15초 기준으로 경고한다. 제동을 2초 이상 밟고 있으면 정차로 보고 무조작에서 뺀다.

**급제동 한 번은 정상으로 둔다.** 앞차를 보고 밟았다면 오히려 깨어 있다는 증거다. 무수정 뒤 급조작이 반복될 때만 주의로 본다.

**조향 토크로 '쏠림'과 '조작'을 나눈다.** 졸음운전의 비틀거림은 운전자가 힘을 주지 않았는데 차가 한쪽으로 가다가, 깨어나 힘을 주며 바로잡는 모습이다. 조향각만 보면 둘 다 조작처럼 보여, 비틀거림이 경고에 대한 응답으로 잘못 잡혔다. 토크가 있으면 힘이 들어가지 않은 조향각 변화는 조작에서 빼고, 토크 없이 쏠렸다가 토크를 주며 돌아오면 한 번만으로 졸음 주의로 본다. 토크가 없으면 의도한 조작과 구별할 수 없어 두 번 반복될 때만 주의로 본다.

**CAN 졸음 판단은 복귀하는 순간에 나온다.** 쏠리는 동안의 작은 조향각 변화만으로는 커브나 바람과 구별되지 않는다. 그래서 정답 라벨(쏠림 시작)보다 약 0.6초 늦다. 쏠리는 동안 눈 감김은 비전이 먼저 잡는다.

**가벼운 심박 이상은 주의에서 멈춘다.** 주행 중 인지 부하만으로도 심박은 오른다. `HR_HIGH` 같은 사유는 응답 확인을 시작하지 않는다. `DROWSY_HINT`는 생체 쪽 설계대로 등급에 영향을 주지 않는다.

**측정 끊김은 회복이 아니다.** 쓰러지면 얼굴이 가려지거나 센서가 떨어질 수 있다. 이때 확인이 취소되면 가장 위험한 순간에 경보가 풀린다.

## 수치의 근거

| 값 | 설정 | 근거 |
|---|---|---|
| 즉시 위험의 눈 감김 | 3초 | Euro NCAP `Tsleep` 3초 고정 [1] |
| 눈 감김 경고 시작 | 2초 | 비전 팀 값. Euro NCAP 미세수면 1–2초의 상한 [1] |
| 눈 감김 단독 응답 창 | 10초 | 2 + 10 = 12초. Euro NCAP 시험의 눈 감김 13초 안에 들도록 정함 [1] |
| 전방 이탈 응답 창 | 12초 | 2 + 12 = 14초. Euro NCAP 시험의 시선 이탈 14초 [1] |
| 근거가 둘 이상일 때 응답 창 | 5초 | 비전 팀 `danger_after_warning_seconds`와 같음. 경고 후 반응 시간에 대한 공개 수치는 찾지 못했다 |
| 무조작 단독 경고 | 15초 | UN R79 핸즈오프 경고 시작 상한을 다룬 논문 [3]. R79 원문은 확인하지 못했다 |
| 쏠림 후 복귀 패턴 | 조용한 시간 2초, 복귀 1.2도(바퀴 기준) 1.5초 안, 손 힘 0.1 Nm | 패턴은 졸음 조향 연구에 나오지만 원문을 확인하지 못했다. **수치는 설계값** |
| 조작 감지 폭, 응답 2회, 정차 추정, 급제동 0.6, 재확인 시간, 30초 | 설정 파일 참고 | **설계값** |

Euro NCAP의 13·14초는 평가 시험에서 운전자가 유지하는 시간이고, 법적 판정 기준은 아니다. EU 2023/2590은 전방 이탈 경고를 50 km/h 이상에서 3.5초, 20 km/h 이상에서 6초로 정한다[2]. 비전의 2초는 이보다 민감하므로 오경보가 많으면 이 범위로 늘려 볼 수 있다.

조향 반전율(SRR)은 쓰지 않았다. 연구들이 운전자별 학습으로 기준을 정하고, 반전을 어떻게 정의하느냐에 따라 값이 크게 달라진다[4]. 고정 임계값을 뒷받침할 수치를 찾지 못했다.

## 사용법

```python
from fusion import FusionEngine, can_from_unity_state

engine = FusionEngine(log_path="fusion_status.jsonl")

# 입력을 받을 때마다. now는 이 프로그램의 시계(time.monotonic() 등)를 쓴다
engine.push_bio(now, assessor.latest())         # BioStatus. 아직 None이면 호출하지 않는다
engine.push_vision(now, vision_engine.update(frame))  # warning_active=False로 돌린 비전 Decision
engine.push_can(now, **can_from_unity_state(vehicle_state))
engine.push_button(now)                         # 버튼이 눌렸을 때

decision = engine.update(now)
decision.level                # normal, caution, danger, unavailable
decision.driver_state         # vehicle_control의 driver_state로 보낸다
decision.reasons              # 판단 근거
decision.response_remaining_s # 응답 확인 중이면 남은 초
```

실차 CAN은 조향을 -1~1, 페달을 0~1로 정규화해서 넣는다. 크루즈 등 차량이 만든 값이면 `driver_input_valid=False`로 넣는다.
`steering_torque`(Nm)를 함께 넣으면 쏠림과 조작을 구별한다. CSV 한 줄은 `can_from_csv_row(row)`로 바꾼다.

## 미리 만든 파일로 재생

엔진은 넘겨받은 시각으로만 판단하므로, 파일 시각을 그대로 넣으면 실시간으로 돌린 것과 결과가 같다. 실시간 연결이 없어도 판단 결과는 그대로 쓸 수 있다.

```bash
python tools/replay_fusion.py --ecg synthetic_ecg_250hz_60s.csv --vision vision.jsonl --can can_caution_drowsy_drift_15s.csv --can-offset 30
```

- `--ecg`: 시각 열과 ECG 열. 측정 폴더의 `biosignals.csv`는 PPG까지 함께 읽는다.
- `--vision`: 한 줄에 `timestamp`, `state`, `reasons`인 JSONL. 비전 브랜치의 `replay_response_events.py`에 빈 이벤트 목록(`[]`)을 넣으면 나온다.
- `--can`: `steering_angle_deg`, `accelerator_pedal_pct`, `brake_pedal_pct`, 선택으로 `vehicle_speed_kph`, `steering_torque_nm`. `ground_truth_state` 열이 있으면 판단과 비교한다.
- 같은 시계로 찍힌 생체신호와 비전은 오프셋 없이 넣는다. 따로 만든 파일은 `--can-offset` 등으로 사건 시작을 맞춘다. 이렇게 만든 결과는 **합성 시나리오**다. 판단 로직이 의도대로 움직인다는 확인이지, CAN과 생체·비전이 실제로 함께 변한다는 근거가 아니다.
- 생체 기준선(10초)과 시작 판단(20초)이 지난 뒤에 사건이 오도록 오프셋을 준다.
- `--steer-full-deg`는 조향 -1~1에 대응하는 각도다. 기본 30도는 바퀴 조향각 기준이다. 핸들 각도 로그면 핸들 최대 각도를 넣는다.

## 사유 코드

| 코드 | 의미 |
|---|---|
| `BIO:*`, `VISION:*` | 각 입력이 낸 사유 |
| `MULTIMODAL_INCAPACITATION` | 서로 다른 근거가 겹쳐 즉시 위험 |
| `NO_RESPONSE:*` | 응답 확인 시간 초과로 위험. 뒤는 확인을 시작한 근거 |
| `RESPONSE_CHECK:*` | 응답 확인 중 |
| `RESPONSE_CONFIRMED`, `RESPONSE_CHECK_CLEARED` | 운전자가 응답함, 근거가 사라져 확인 취소 |
| `CAN:NO_INPUT`, `CAN:DRIFT_CORRECTION`, `CAN:ERRATIC_CONTROL`, `CAN:HARD_BRAKE` | 무조작, 토크 없이 쏠린 뒤 복귀, 쏠림 후 복귀·급제동 반복, 최근 급제동 |
| `DRIVER_MONITORING_LOST`, `STARTING` | 비전과 생체 모두 측정 불가, 시작 중 |
| `HOLD_PREVIOUS_LEVEL` | 주의 해제 전 5초 유지 |

## 확인 결과

`tests/test_fusion.py`는 합성 입력으로 시나리오를 검사한다. 비전 브랜치의 실제 `TemporalDecisionEngine`과 실제 `BioSignalMonitor`를 합성 특징·합성 심전도에 연결한 결과는 다음과 같다.

| 시나리오 | 결과 |
|---|---|
| 정상 주행 | 정상 유지 |
| 심정지 + 3초 뒤 쓰러짐 + 조작 끊김 | 4.1초에 주의, 5.0초에 위험 |
| 무맥성(ECG 유지, PPG 소실) + 눈 감김 + 조작 끊김 | 4.0초에 주의, 8.1초에 위험 |
| 빈맥 165 bpm + 운전자 조작 계속 | 주의 유지, 위험 없음 |
| 눈 감김 4초 후 깨어나 조작 | 2초에 주의(`D`), 위험 없이 약 10초에 정상 복귀 |
| 눈 감김 지속 + 조작 끊김 | 2초에 주의, 7초에 위험 |

시간은 사건 시작 기준이다.

### 합성 파일 재생

합성 ECG(60초)와 합성 CAN(`can_caution_drowsy_drift_15s.csv`, 30초에 배치)으로 재생한 결과다.

| 입력 | 결과 |
|---|---|
| CAN만 | 쏠림 두 번 모두 복귀 시점에 졸음 주의(`D`). 첫 번째는 정답 라벨보다 0.6초 늦음 |
| ECG + CAN | 기준선 뒤 정상, CAN 사건에서 주의, 사건 뒤 약 6초에 정상 복귀 |
| ECG + 비전(눈 감고 졸다 깸) + CAN | 눈 감김 2초에 주의와 응답 확인, 눈을 뜨자 확인 취소, 위험 없음 |
| ECG + 비전(두 번째는 계속 눈 감음) + CAN | 복귀 조향을 응답으로 인정한 뒤 10초 뒤 재확인, 59.4초에 위험 |

정답 라벨과 0.1초 단위로 맞는 비율은 약 45%다. 라벨은 사건이 일어난 2초만 `Caution`이지만, 이 판단은 사건 뒤에도 주의를 유지한다. 졸음은 2초 만에 사라지지 않고, Unity 경고가 반복해서 뜨는 것을 막기 위해서다. 두 번 반복되면 60초 동안 유지한다. 라벨처럼 짧게 끝내려면 `can_note_s`와 `abrupt_repeat_window_s`를 줄인다.

## 한계

- **실제 영상, 실제 CAN, 실주행으로는 아직 검증하지 않았다.** 위 결과는 설계대로 동작한다는 확인이지 정확도 근거가 아니다. 오경보율과 놓침률은 측정하지 못했다.
- 비전과 Unity 코드는 다른 브랜치에 있어 실시간 연결은 하지 않았다.
- CAN 메시지 정의(DBC)가 없어 Unity의 `vehicle_state` 형식을 기준으로 만들었다. 조작 감지 폭은 키보드 조작이 기본인 Unity 기준이라 실차나 핸들 컨트롤러에서는 다시 정해야 한다.
- 합성 CAN은 정상 구간의 조향 토크가 0.1 Nm 미만이라 손에 힘이 없는 것으로 판단된다. 실차에서 직진할 때 운전자가 주는 토크는 확인하지 못했으므로 `hands_on_torque_nm`은 실측으로 정해야 한다.
- 속도 신호가 없으면 정차를 제동으로만 추정한다. 제동 없이 멈춘 경우와 주차 상태는 구분하지 못한다. 눈 감김이나 쓰러짐의 응답 확인은 정차 중에도 진행된다.
- 휴대전화 감지는 비전 `Decision`의 사유에 들어오지 않아 판단에 쓰이지 않는다.

## 다른 파트에 필요한 변경

- **Unity:** 건강·시스템 경고 코드가 없어 `A`를 임시로 쓴다. 지금은 심박 이상에도 "전방주시 이탈" 문구가 나온다.
- **Unity:** `D`·`A` 경고는 진입 때 한 번만 울린다. 응답 확인 중에는 "핸들을 움직이세요" 같은 안내와 반복 경고가 필요하고, Cruise에서 응답할 수단도 필요하다. 지금은 Cruise에서 핸들 조작이 무시되고 응답 버튼도 없어, 깨어 있어도 근거가 계속되면 위험까지 올라간다.
- **비전:** `perclos_caution_ratio`가 0.35인데, 문헌에서 찾은 기준은 8–12%다[5]. 측정 방식(눈 감김 판정 기준)이 달라 직접 비교는 어렵지만 재검토가 필요하다.
- **CAN:** 차속을 추가하면 정차 판단이 정확해진다.
