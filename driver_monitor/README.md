# Driver Monitor: 눈 감김 · 졸음(머리 숙임) · 핸들 파지 · 심박(rPPG)

웹캠 1대로 운전자의 **눈 감김, 머리 숙임/끄덕임, 하품, 손 핸들 파지 여부, 심박수(rPPG)**를 실시간으로 판정합니다.
MediaPipe Tasks API(FaceLandmarker 478점 + blendshape + 3D 머리 자세, HandLandmarker 21점×2)를 씁니다.

## 설치 / 실행

```bash
py -m pip install -r requirements.txt
py main.py                     # 첫 실행 때 모델(.task) 2개를 models/ 에 자동으로 받습니다
py -m pytest tests -q          # 판정 로직 테스트 (모델/카메라 없이)
```

- Windows에서는 `python` 대신 `py`를 쓰세요. `python`은 Microsoft Store 별칭이 잡힐 수 있습니다.
- **경로에 한글이 없는 폴더**(예: `C:\Users\<이름>\driver_monitor`)에 두세요. 모델 파일은 파이썬으로 읽어서 바이트(`model_asset_buffer`)로 MediaPipe에 넘깁니다.
- OpenCV는 `opencv-contrib-python` 하나만 설치하세요. `opencv-python`과 같이 깔리면 충돌합니다.
- Windows에서는 카메라를 MSMF로 열되, 하드웨어 변환(`OPENCV_VIDEOIO_MSMF_ENABLE_HW_TRANSFORMS=0`)을 끕니다(`open_camera()`). 이 옵션이 켜져 있으면 여는 데 10초 넘게 걸려 멈춘 것처럼 보입니다. 실측(1280x720): MSMF 30fps, DirectShow 10fps(YUY2, MJPG 지정 시 15fps). MSMF로 안 열리면 DirectShow로 자동 전환합니다. `--cam-settings`를 주면 설정창 때문에 DirectShow로 엽니다(FPS가 낮아지니 설정만 바꾸고 다시 실행하세요).

| 옵션 | 설명 |
|---|---|
| `--source 1` / `--source clip.mp4` | 다른 카메라 번호, 또는 녹화 영상 |
| `--mirror` | 좌우 반전 (셀카 화면처럼 보기) |
| `--no-hands` | 손 검출 끄기 (저사양 PC에서 FPS 향상) |
| `--no-rppg` | 심박 추정 끄기 |
| `--cam-settings` | (Windows) 카메라 드라이버 설정창 열기. 여기서 자동 노출/화이트밸런스를 끄면 심박 정확도가 올라갑니다 |
| `--lock-camera` | 자동 노출/화이트밸런스 끄기를 코드로 시도 (카메라마다 지원 여부가 다름) |
| `--log run.csv` | 프레임별 수치를 CSV로 저장 (임계값 튜닝용) |
| `--dump-config` | 기본 설정을 `config.json`으로 저장 (이후 수정해서 사용) |
| `--unity` | Unity 차량 연동 (아래 "Unity 차량 연동" 참고) |

**단축키:** `Q` 종료 · `C` 재캘리브레이션 · `W` 핸들(타원) 영역 그리기 · `R` 사각형 영역 그리기 · `X` 영역 삭제 · `M` 좌우 반전 · `H` 도움말 · `S` 스크린샷
`--unity`일 때 추가: `A` 정속 주행/수동 전환 · `G` 비상 상황 해제 · `T` 시험용 비상 개입

## Unity 차량 연동 (`--unity`)

팀원 Unity 프로젝트(`코드/HKMC_CAN_LOG/unity_stage1_basic_vehicle`)에 **Unity 쪽 코드 수정 없이** 붙습니다. 통신 규격(TCP 5001, 줄 단위 JSON `vehicle_state` / `vehicle_control`)이 팀원 `vehicle_tcp_server.py`와 같고, driver_monitor가 그 서버 자리를 대신합니다. **두 서버를 동시에 켜지 마세요(같은 포트).**

```bash
py main.py --unity
```
위 명령을 먼저 실행한 뒤 Unity에서 `BasicDrivingStage1` 씬을 Play하면 됩니다. 순서는 바뀌어도 되고, Unity가 1초마다 재접속합니다.

| 단계 | 조건 | 차량 |
|---|---|---|
| CRUISE | 시작 시 기본 | 30 km/h 정속 + 오른쪽 차로 중앙 유지 (`A`로 수동 전환하면 Unity에서 키보드 운전) |
| ALERT | `EYES CLOSED` · `HEAD DOWN` · `FACE NOT VISIBLE`이 **DANGER인 상태가 2초** 이어짐 | 비상등 on, 속도 유지. 2초 안에 운전자가 1초 이상 정상으로 돌아오면 취소 |
| DECEL | ALERT 2초 뒤 | 단계적 감속(6 km/h/s) + 갓길 이동. **이후 운전자가 깨어나도 정차까지 진행** |
| STOPPED | 속도 0 | e-Call MSD를 `ecall_log/msd_*.json`에 저장(가상 위치, 감지~정차 타임라인 포함). `G`로 해제하면 다시 정속 주행 |
| ROAD_END | 정속 주행 중 z > 350 (도로가 400m) | 차로 안에서 정차. Unity 창에서 `R`(출발점 복귀)을 누르면 다시 주행 |

- PERCLOS, 핸들 이탈, 하품, 끄덕임은 경고만 하고 차량에 개입하지 않습니다(`takeover_reasons`로 변경 가능).
- 카메라 루프가 0.5초 이상 멈추면 명령 전송을 멈춥니다. 그러면 Unity가 0.75초 뒤 스스로 제동합니다(팀원 코드의 페일세이프).
- e-Call은 파일로 저장만 합니다. 외부 서버나 실제 긴급번호로는 보내지 않습니다. MSD는 개입이 확정되는 순간 만들어지고(감지 후 1초 이내), 정차하면 위치와 시각을 채워 저장합니다.
- Unity 화면에는 비상등이나 e-Call 표시가 없습니다(팀원 HUD에 아직 없음). 상태는 driver_monitor 화면 왼쪽 아래 `UNITY` 줄에서 확인합니다. 보내는 JSON에 `phase`, `dms_level`, `dms_reasons`, `msd_id`를 함께 넣어 두었으니, Unity HUD에서 이 필드를 읽게 하면 바로 표시할 수 있습니다.

| 설정 키 | 기본값 | 설명 |
|---|---|---|
| `cruise_kph` | 30 | 정속 주행 속도. 도로가 400m라서 빠르면 금방 끝납니다 |
| `takeover_reasons` | 눈 감김, 고개 숙임, 얼굴 소실 | 차량 개입을 일으키는 DANGER 원인 |
| `takeover_after_s` / `alert_s` | 2.0 / 2.0 | 개입까지 대기 시간 / 감속 전 경고 시간 |
| `decel_kph_per_s` | 6.0 | 감속 비율 |
| `pull_over` | true | 갓길 이동 여부 |
| `lane_center_x` / `shoulder_center_x` / `road_end_z` | 0.75 / 4.5 / 350 | 팀원 씬 좌표 기준 |
| `unity_host` / `unity_port` | 127.0.0.1 / 5001 | Unity를 다른 PC에서 돌리면 host를 `0.0.0.0`으로 (방화벽 허용 필요) |
| `vehicle_id`, `virtual_lat/lon`, `ecall_dir` | | MSD 내용과 저장 위치 |

**실측 (팀원 씬을 Unity 6000.6으로 빌드해 폐루프 시험, 카메라 대신 가짜 판정 입력):**
- 정속: 30 ± 0.5 km/h, 차로 중앙 ± 0.003 m
- 눈 감김 DANGER부터 개입까지 2.0초, 감속 시작까지 4.0초, 갓길(x = 4.42) 정차까지 12.5초
- MSD 생성은 개입 확정 후 1.9 ms

## 사용 순서

1. **캘리브레이션 (시작 후 5초):** 정면을 보고 눈을 평소처럼 뜨고 있으세요. 이 사람의 평소 EAR(눈 뜬 정도)과 머리 각도를 기준값으로 잡습니다. 자세나 조명이 바뀌면 `C`를 누르세요.
2. **핸들 영역 지정:** `W`를 누르고 화면의 핸들 테두리를 마우스로 드래그합니다. `wheel_roi.json`에 저장되어 다음 실행 때 자동으로 불러옵니다.
   - **핸들이 아직 없을 때:** 책상 위 접시나 원형 판을 핸들처럼 두고 `W`로 그리거나, `R`로 손을 올려둘 사각형 영역을 지정해서 테스트하면 됩니다. 영역을 지정하지 않으면 손은 검출만 하고 경고는 내지 않습니다.
3. 상단 바 색으로 상태를 표시합니다. 여러 조건이 겹치면 가장 높은 레벨을 씁니다.

| 레벨 | 값 | 화면 | 소리 |
|---|---|---|---|
| OK | 0 | 초록 바 | 없음 |
| CAUTION | 1 | 연한 노랑 바 (`CAUTION ONE HAND ...`) | 없음 |
| WARNING | 2 | 주황 바 | 2초마다 낮은 경고음 |
| DANGER | 3 | 빨강 바 + 빨강 테두리 | 0.6초마다 높은 경고음 |

   `--log` CSV의 `level` 열에는 위 숫자가, `level_name` 열에는 이름이 들어갑니다. (예전에는 WARN=1, DANGER=2였습니다.)

## 판정 알고리즘

| 항목 | 방법 | 기본 임계값 |
|---|---|---|
| 눈 감김 | **EAR** = (눈 세로 2개 거리) / (2 × 가로). 개인 기준 EAR × 0.70 미만이면 감김 | 연속 1.2초 WARN, 2.5초 DANGER |
| 깜빡임 | 0.05~0.5초 동안의 짧은 감김을 1회로 집계 | 분당 횟수 표시 |
| PERCLOS | 최근 60초 중 눈 감긴 프레임 비율 (졸음 연구에서 표준으로 쓰는 지표) | 15% WARN, 30% DANGER |
| 머리 숙임 | 얼굴 3D 변환행렬에서 pitch 추출, 기준 대비 +15° 이상이면 숙임 | 1.5초 WARN, 3초 DANGER |
| 끄덕임 | 0.3초 이상 숙였다 드는 동작을 60초 안에 카운트 | 3회 WARN |
| 얼굴 소실 | 고개를 푹 숙여 얼굴이 안 잡히는 경우. 직전에 숙이던 중이었으면 DANGER | 2초 |
| 하품 | MAR(입 세로/가로) > 0.6이 1초 이상 | 5분에 3회 WARN |
| 핸들 파지 | 손 key point 10개(손목, MCP, 손끝) 중 35% 이상이 **핸들 림(타원 안쪽 55%~바깥 115% 사이)**에 있으면 파지. 핸들 중앙에 손을 올린 경우는 파지로 보지 않음 | 핸들 영역(`W`/`R`)을 지정해야 판정. 미지정이면 경고 없음 (`wheel not set` 표시) |
| 두 손 이탈 | 핸들 위 손이 0개. **손이 화면에 안 보이는 경우(검출 0개)도 포함.** 검출이 0.3초보다 짧게 끊기는 건 무시하고, 시간은 실제로 손을 뗀 순간부터 잼 | 2초 WARN, 5초 DANGER. 화면에 경과 시간과 다음 단계까지 남은 시간 표시 |
| 한 손 운전 | 핸들 위 손이 1개 (같은 0.3초 유예 적용) | 3초 **CAUTION** (경고음 없음). 남은 한 손도 떼면 '두 손 이탈'로 넘어감 |

### 심박 (rPPG)

1. 얼굴 랜드마크로 ROI를 잡습니다. 기본은 **이마만** 쓰고, 이마를 쓸 수 없을 때만 **양 볼**을 더합니다(`rppg_roi_mode`). 지금 쓰는 영역은 화면의 보라색 외곽선과 HUD의 `ROI` 줄에 표시됩니다.
   - **이마 영역:** 눈썹 윗선(105·107·9·336·334), 이마 가운데 줄(69·108·151·337·299), 얼굴 윤곽 맨 위(67·109·10·338·297) 사이를 보간해서 만듭니다. 아래 변은 눈썹에서 약 0.6cm, 위 변은 머리선에서 약 0.7cm 떨어집니다. 예전 ROI는 얼굴 윤곽 맨 위까지 들어가서 머리선이 섞였습니다.
   - **픽셀 거르기:** 반사광과 너무 어두운 픽셀을 빼고, 볼 피부와 밝기나 색이 다른 픽셀(앞머리, 눈썹, 모자, 짙은 그림자)도 뺍니다. 조명 때문에 픽셀 대부분이 빠지면 피부색 거르기는 자동으로 꺼집니다.
   - **`forehead_first`(기본):** 다음 두 경우에 이마+볼로 바꿉니다. 이마 유효 픽셀이 `rppg_forehead_min_px`보다 적은 상태가 0.5초 이어질 때(`forehead covered`), 이마 SNR이 `rppg_snr_thr`보다 낮은 상태가 `rppg_roi_fallback_s` 이어질 때(`forehead low SNR`). 이마 상태가 다시 좋아져서 `rppg_roi_recover_s` 동안 유지되면 이마로 돌아옵니다.
   - 이마 버퍼와 이마+볼 버퍼는 따로 쌓입니다. 그래서 ROI를 바꿔도 신호가 섞여 튀지 않고, 10초를 다시 기다릴 필요도 없습니다.
2. 그 영역의 평균 RGB를 매 프레임 기록하고, 타임스탬프 기준으로 30Hz로 다시 샘플링합니다. 웹캠 FPS가 흔들려도 보정됩니다.
3. **POS 알고리즘**(Wang et al., 2017)으로 피부색의 미세한 맥동을 뽑습니다. 흑백(IR) 영상이면 자동으로 밝기 기반 방식으로 바뀝니다.
4. 최근 10초를 FFT해서 42~180 bpm 대역의 최대 피크를 심박수로 씁니다. 1초마다 갱신하고, 최근 유효값 5개의 중앙값을 표시합니다.
5. **SNR(dB)**로 신호 품질을 판단합니다. −2 dB 미만이면 `?`를 붙이고 회색 파형으로 표시합니다. 잡음만 넣었을 때는 90%가 −3 dB 이하로 나왔습니다.
6. **HRV(RMSSD)**는 실험적 기능이고, SNR 8 dB 이상일 때만 표시합니다. 잡음이 있으면 박동 간격이 흔들려 RMSSD가 실제보다 크게 나옵니다. 합성 신호 기준으로 잡음이 없으면 오차가 약 5%지만, 잡음이 조금만 있어도 수십 ms씩 부풀었습니다.
7. **졸음 연동(기본 꺼짐):** 캘리브레이션이 끝난 뒤 유효 추정 30개(약 30초)의 중앙값을 기준 심박으로 잡습니다. `"rppg_alert": true`로 켜면 기준보다 10% 이상 낮은 상태가 30초 이어질 때 `HR LOW` 경고를 냅니다. 개인차가 커서 보조 지표로만 쓰는 것을 권합니다.

**rPPG 잘 나오게 하는 법**
- 처음 **10초는 가만히** 있어야 첫 값이 나옵니다(`measuring... %` 표시).
- 얼굴에 **밝고 일정한 조명**이 필요합니다. 모니터 불빛만 있거나 형광등이 깜빡이면 신호가 약해집니다.
- 카메라의 **자동 노출과 자동 화이트밸런스를 끄세요**(`--cam-settings`). 켜져 있으면 밝기가 계속 바뀌어 신호가 묻힙니다.
- 실제 카메라 FPS가 15 미만이면 추정하지 않습니다. 어두우면 웹캠이 FPS를 스스로 낮추니 조명을 밝게 하세요. `--no-hands`로 처리 속도를 올리는 것도 도움이 됩니다.
- 정확도는 스마트워치나 손가락 맥박 센서와 비교해서 확인하세요. `--log`의 `hr` 열과 비교하면 됩니다. 의료용 측정이 아닌 참고용 추정값입니다.

모든 값은 `dms/config.py`에 있고 `config.json`으로 덮어쓸 수 있습니다(`py main.py --dump-config`로 기본값 파일 생성).

### 주요 설정 (손 / 심박 ROI)

| 키 | 기본값 | 설명 |
|---|---|---|
| `hands_off_warn_s` / `hands_off_danger_s` | 2.0 / 5.0 | 두 손 이탈(손이 안 보이는 경우 포함) WARN / DANGER 시간 |
| `hands_grace_s` | 0.3 | 손 검출이 이보다 짧게 끊기면 무시 |
| `one_hand_caution_s` | 3.0 | 한 손 운전이 이만큼 이어지면 CAUTION. 예전 `one_hand_warn_s`(10초 WARN)는 없어졌습니다 |
| `rppg_roi_mode` | `"forehead_first"` | `"forehead"` 이마만 / `"forehead_first"` 이마 우선 / `"all"` 이마+양 볼(예전 방식) |
| `rppg_skin_mask` | `true` | 볼 피부색과 다른 픽셀(앞머리, 눈썹, 모자) 제외 |
| `rppg_forehead_min_px` | 600 | 이마 유효 픽셀 기준. 얼굴이 작게 잡히는 카메라면 낮추세요 (HUD `ROI` 줄의 `px` 값 참고) |
| `rppg_roi_fallback_s` | 5.0 | 이마 SNR이 낮은 상태가 이만큼 이어지면 볼 추가 |
| `rppg_roi_recover_s` | 5.0 | 이마가 다시 좋아진 상태가 이만큼 이어지면 이마로 복귀 |

## 튜닝 팁

- **머리를 숙이는데 `Pitch d`가 음수로 나오면** `config.json`에서 `"head_pitch_sign": -1`로 바꾸세요. 카메라 각도에 따라 부호가 반대로 나올 수 있습니다.
- **안경 반사 때문에 눈 감김이 잘 안 잡히면** `"eye_method": "both"`로 바꾸세요. MediaPipe blendshape의 eyeBlink 점수를 함께 사용합니다.
- **핸들 위의 손이 잘 안 잡히면** `wheel_margin`을 키우거나 `wheel_point_ratio`를 0.25 정도로 낮추세요. 손가락을 실제로 쥐었을 때만 인정하려면 `"require_curl": true`로 설정합니다.
- 차량에서는 밤에 쓰는 경우가 많습니다. **IR 카메라와 IR LED 조명** 조합을 추천합니다(MediaPipe는 흑백 IR 영상에서도 동작합니다).
- `--log`로 CSV를 남긴 뒤 EAR과 pitch 분포를 보고 임계값을 정하는 것이 가장 정확합니다.

## 구조

```
main.py              카메라 루프, 키/마우스 입력, 경고음, CSV 로그
dms/perception.py    MediaPipe 얼굴/손 랜드마크 → FaceObs / HandObs
dms/geometry.py      EAR, MAR, 머리 자세(euler), 손가락 말림 계산
dms/monitor.py       캘리브레이션 + 시간 기반 상태 판정 → OK / CAUTION / WARN / DANGER
dms/wheel.py         핸들 ROI (타원 링 / 사각형) + 파지 판정, JSON 저장
dms/rppg.py          rPPG: ROI(이마 우선) 추출, POS, FFT 심박 + SNR, HRV(RMSSD)
dms/ui.py            화면 오버레이
dms/vehicle_link.py  Unity 차량 연동: TCP 서버 + 정속 주행 / 비상 정차 / e-Call MSD
tests/test_logic.py  합성 데이터로 판정 로직 검증 (py -m pytest tests -q)
tests/test_rppg.py   합성 맥파(조명 변화, 잡음, FPS 흔들림 포함)로 심박/HRV, ROI 모드 검증
tests/test_vehicle_link.py  가상 차량 모델 + 가짜 Unity 클라이언트로 연동 로직 검증
```

`monitor.py`는 모델과 분리되어 있습니다. 그래서 나중에 IR 카메라 전용 모델이나 YOLO 손 검출기로 교체해도 `FaceObs`/`HandObs` 형식만 맞추면 판정 로직은 그대로 쓸 수 있습니다.

## 한계

- 핸들 파지는 2D 영상 기준입니다. 손이 핸들 **앞쪽 허공**에 있어도 영역과 겹치면 파지로 판정될 수 있습니다. 정밀하게 하려면 핸들 정전식 센서나 뎁스 카메라를 함께 쓰거나, 파지/비파지 영상을 모아 분류기를 학습시키는 것이 좋습니다.
- rPPG는 **머리를 움직이거나 조명이 바뀌면**(주행 중 햇빛, 터널, 그림자) 정확도가 크게 떨어집니다. 이럴 때는 SNR이 낮아져 값이 `?`로 표시되거나 갱신되지 않습니다.
- 선글라스를 쓰면 눈 판정이 불가능합니다. 이때는 머리 자세, 끄덕임, 하품 지표에 의존합니다.
